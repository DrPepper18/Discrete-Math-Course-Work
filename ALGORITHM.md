# Алгоритм решения кубика Рубика методом коммутаторов

## Математическая основа

### Группа G кубика Рубика
Порядок группы: |G| = 43,252,003,274,489,856,000

Порождающие элементы: U, D, L, R, F, B (повороты шести граней)

### Три инварианта (законы сохранения)

Состояние куба описывается кортежем (σc, σe, x, y):
- σc ∈ S8 — перестановка углов
- σe ∈ S12 — перестановка рёбер  
- x ∈ Z3^8 — вектор ориентации углов
- y ∈ Z2^12 — вектор ориентации рёбер

**Инвариант 1: Чётность перестановок**
```
sgn(σc) = sgn(σe)
```
Знаки перестановок углов и рёбер должны совпадать.

**Инвариант 2: Ориентация углов**
```
Σxᵢ ≡ 0 (mod 3)
```
Сумма поворотов углов кратна 3.

**Инвариант 3: Ориентация рёбер**
```
Σyᵢ ≡ 0 (mod 2)
```
Сумма переворотов рёбер кратна 2.

## Алгоритм решения

Алгоритм реализован в `backend/rubik/solver.py` и строится по пяти этапам:

0. **Выравнивание чётности.** Если уголковая перестановка нечётна, применяется
   один поворот `U`. Это делает перестановки углов и рёбер чётными.
1. **Перестановка углов.** Решается 3-циклами углов с помощью сопряжённого
   примитива `c3`.
2. **Перестановка рёбер.** Аналогично решается 3-циклами рёбер через примитив
   `e3`.
3. **Ориентация углов.** Исправляется сопряжённым примитивом `ct`, который
   меняет ориентацию углов без перестановки.
4. **Ориентация рёбер.** Исправление выполняется сопряжённым примитивом `ef`.

### Примитивы

| Примитив | Эффект | Длина |
|----------|--------|-------|
| `c3` | 3-цикл трёх углов | 8 |
| `e3` | 3-цикл трёх рёбер | 8 |
| `ct` | твист пары углов | 20 |
| `ef` | переворот пары рёбер | 24 |

### Сопряжение и setup

Каждый примитив применяется через подготовку `S · P · S⁻¹`, где `S` —
setup-последовательность, а `P` — базовый примитив. Это позволяет перенести
эффект на нужные слоты.

Setup-последовательности строятся методом BFS по образам помеченных слотов.
Поворот действует на слоты фиксированной перестановкой независимо от их
содержимого, поэтому BFS остаётся компактным.

### Структура реализации

### Файл `solver.py`

**Функция `_check_invariants(state)`**
- Проверяет три инварианта группы G
- Гарантирует корректность входного состояния
- Возвращает (valid: bool, message: str)

**Функция `_bfs_setups(marks, read, slots)`**
- Находит кратчайшие setup-последовательности методом BFS
- Для каждого образа помеченных слотов возвращает минимальную подготовку
- Используется для всех четырёх типов макросов

**Функция `_macro_effect(moves, read)`**
- Применяет макро к собранному кубу (solved())
- Возвращает эффект на уровне деталей (perm, ori)
- Показывает как макро переставляет детали

**Функция `_build()`**
- Строит библиотеки макросов для всех этапов один раз при импорте
- Для перестановок (corner3, edge3): сохраняет все 3-циклы
- Для ориентаций (twist, flip): сохраняет все дельта-изменения
- Выбирает кратчайший макро для каждого эффекта

**Функция `_solve_perm(r, read, macros, n)`**
- Решает перестановку деталей методом жадного перебора
- На каждом шаге: ищет макро, который даёт максимальное улучшение
- Проверяет: нет ли застревания на неразрешимой конфигурации

**Функция `_solve_orient(r, read, macros, mod)`**
- Решает ориентацию деталей
- Минимизирует количество неправильно ориентированных деталей
- Использует эвристику: число неправильно ориентированных + их сумма

**Функция `solve(state)`**
- Главная функция решения куба
- Проверяет инварианты
- Выполняет 5 этапов последовательно
- Возвращает сжатую (compressed) последовательность ходов

**Функция `_compress(seq)`**
- Оптимизирует последовательность ходов
- Схлопывает подряд идущие повороты одной грани
- Пример: R R R → R', R U U → R U2

## Сложность и производительность

### Гарантии
- Алгоритм **всегда** находит решение за конечное число шагов
- Корректность гарантирована математической теорией групп

### Типичные размеры решений
- Собранный куб: 0 ходов
- Одиночный ход скрэмбла: 60-180 ходов
- Случайный скрэмбл (5-20 ходов): 150-250 ходов

### Оптимальность
- Метод коммутаторов НЕ даёт оптимальные решения
- Оптимальное решение требует IDA* или других методов поиска
- Но коммутаторный метод гарантированно решает за разумное время

## Примеры использования

### Python API
```python
from backend.rubik.state import solved, scramble, apply_sequence
from backend.rubik.solver import solve

# Генерируем случайный скрэмбл
state, scramble_seq = scramble(n=20)

# Решаем куб
solution = solve(state)

# Проверяем
final_state = apply_sequence(state, solution)
assert is_solved(final_state)
```

## Инструменты и файлы

- `geometry.py`: Геометрия кубика, нумерация сегментов, ходы
- `state.py`: Операции на уровне перестановок (54 сегмента)
- `pieces.py`: Извлечение деталей (углы, рёбра) из перестановок
- `cycles.py`: Алгебра перестановок (циклы, чётность, композиция)
- `solver.py`: Основной алгоритм решения (5 этапов)
- `find_primitives.py`: Поиск примитивов-коммутаторов перебором
- `app.py`: FastAPI веб-приложение
- `index.html`: Фронтенд с 3D визуализацией
- `app.js`: Трёхмерный рендерер кубика
