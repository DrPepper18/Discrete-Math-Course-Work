## Реализованные компоненты

### 1. Проверка инвариантов (`_check_invariants`)
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L21)

**Что проверяет:**
- Чётность перестановок углов = чётность перестановок рёбер
- Сумма ориентаций углов ≡ 0 (mod 3)
- Сумма ориентаций рёбер ≡ 0 (mod 2)

**Возвращает:** (valid: bool, message: str)

**Использование:**
```python
valid, msg = _check_invariants(state)
if not valid:
    raise ValueError(f"Невалидное состояние: {msg}")
```

### 2. Построение библиотек макросов (`_build`)
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L94)

**Что делает:**
1. Для перестановок (углы/рёбра): строит все возможные 3-циклы через сопряжение примитива
2. Для ориентаций: строит все возможные дельта-изменения ориентации
3. Использует BFS для поиска кратчайших setup-последовательностей
4. Сохраняет в памяти при импорте модуля (`_LIB = _build()`)

**Данные:**
- `_LIB['corner3']` — макросы для 3-циклов углов
- `_LIB['edge3']` — макросы для 3-циклов рёбер
- `_LIB['twist']` — макросы для ориентации углов
- `_LIB['flip']` — макросы для ориентации рёбер

**Примитивы (базовые коммутаторы):**
```python
PRIM = {
    'c3': "R F R' B2 R F' R' B2".split(),          # 8 ходов
    'e3': "R2 U2 R2 F2 R2 U2 R2 F2".split(),       # 8 ходов
    'ct': "R F R' B2 R F' R' B2 L U B2 R F R' B2 R F' R' U' L'".split(),  # 20 ходов
    'ef': "R2 U2 R2 F2 R2 U2 R2 F2 U R U' B F2 R2 U2 R2 F2 R2 U2 R2 B' U R' U'".split(),  # 24 хода
}
```

### 3. BFS поиск setup-последовательностей (`_bfs_setups`)
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L71)

**Назначение:**
- Находит кратчайшие последовательности ходов, подводящие детали в рабочую зону
- Работает на уровне слотов (не зависит от содержимого)

**Параметры:**
- `marks` — помеченные слоты (tuple из 2-3 индексов)
- `read` — функция для чтения деталей (read_corners или read_edges)
- `slots` — список слотов для детали

**Возвращает:**
- Dict: образ-кортеж → список ходов
- Ключ — текущий образ помеченных слотов
- Значение — setup-последовательность для достижения этого образа

### 4. Жадное решение перестановки (`_solve_perm`)
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L166)

**Алгоритм:**
1. На каждом шаге проверяет, какие детали не на месте
2. Перебирает все макросы из библиотеки
3. Для каждого макроса: применяет его к текущей перестановке
4. Выбирает макро с максимальным улучшением (минимальное количество ошибок)
5. Повторяет до полного решения

**Композиция макроса с перестановкой:**
```python
# Если M это перестановка из макроса, perm это текущая перестановка деталей
new_perm = [perm[M[s]] for s in range(n)]
```

### 5. Жадное решение ориентации (`_solve_orient`)
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L183)

**Отличие от `_solve_perm`:**
- НЕ меняет перестановку (макросы сохраняют M[s] = s)
- Добавляет дельта-изменение ориентации к каждому слоту
- Минимизирует пару (кол-во неправильных, сумма ориентаций)

**Применение дельты:**
```python
new_ori = [(ori[s] + delta[s]) % mod for s in range(len(ori))]
```

### 6. Основная функция solve
**Место:** [solver.py](c:\Users\Dima\misis-discrete-course-work\backend\rubik\solver.py#L202)

**Последовательность этапов:**
1. Проверка инвариантов
2. Этап 0: Выравнивание чётности (если нечётная)
3. Этап 1: Решение перестановки углов
4. Этап 2: Решение перестановки рёбер
5. Этап 3: Решение ориентации углов
6. Этап 4: Решение ориентации рёбер
7. Финальное сжатие решения

## Производительность и эффективность

### Типичные результаты
| Скрэмбл | Ходов до | Решение | Итого ходов |
|--------|---------|---------|-------------|
| Собранный куб | 0 | - | 0 |
| R | 1 | U R' F R' B2 R F' R' ... | ~180 |
| U | 1 | U R' F R' B2 R F' R' ... | ~67 |
| R U F | 3 | ... | ~150 |
| 20 ходов | 20 | ... | ~194-207 |

### Сложность

**Время:**
- Построение библиотек (`_build`): O(6^k) где k — глубина BFS (обычно k=6-8)
- Решение: O(n_iterations × macros.length) где n_iterations обычно < 100

**Память:**
- Каждая библиотека: сотни-тысячи макросов
- Общая память: ~10-50 МБ

**Гарантии:**
- Всегда находит решение за конечное число шагов
- Не оптимально, но разумно по длине (150-250 ходов для случайного скрэмбла)

## Возможные ошибки и отладка

### Инвариант не выполнен
**Причина:** Неверное состояние куба (невозможно получить вращением)
**Решение:** Проверить функцию `apply_move` в `geometry.py`

### Решение не сходится
**Причина:** 
- Неверная композиция перестановок в `_solve_perm`
- Ошибка в `read_corners` или `read_edges`
**Решение:** Запустить тесты, добавить assert-ы

### Длинные решения
**Причина:** Коммутаторный метод не оптимален
**Решение:** Использовать другой метод (IDA*, Kociemba)
